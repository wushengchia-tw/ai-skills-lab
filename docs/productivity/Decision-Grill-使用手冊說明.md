# Decision-Grill 使用手冊說明

**適用版本：v0.1**

Decision-Grill 是把模糊想法整理成可確認決策的逐步訪談工具。它是「決策訪談與整理工具」，不是執行代理或實作工具：它不會替你寫程式、修改檔案、執行命令、部署，或替你做最後決定。

## Decision-Grill 是什麼

Decision-Grill 透過一次只處理一個重要問題的對話，協助你釐清：想達成什麼、哪些事實尚未知、哪些選擇還沒決定、有哪些限制與風險，以及怎樣才算可接受的結果。

它會在本次對話中維護一份 **decision ledger（決策紀錄）**，讓每個重要問題和回答都有可追蹤的狀態；最後會產出一份可供你確認的決策摘要。它提供建議與替代方案，但真正的商業、產品或個人決定仍由你確認。

這份摘要不是法律、醫療、會計、投資或政府機關意見。遇到高風險議題，請把需要驗證的事項交由合格的律師、會計師、醫師、顧問、公司負責人或主管機關確認。

## 適合與不適合的情境

適合用在下列情況：

- 比較兩個或多個供應商、工具、採購方案或推出方案。
- 整理投資、商業、產品或專案選擇的決策條件。
- 分出哪些是「尚待查明的事實」，哪些是「尚未做出的選擇」。
- 記錄問題為已回答、受阻或被新決定取代的原因。
- 資訊仍不完整時，先整理待研究事項、風險與下一步。

不適合用在下列情況：

- 要求直接寫程式、修改檔案、執行命令、部署或替你完成實作。
- 把龐大、跨多階段的人生或公司目標一次放進單一訪談。
- 想跳過必要的事實、風險或確認，直接宣稱已完成。
- 把工具的建議或摘要當成法律、醫療、會計或投資保證。

## 使用前準備

先確認目前使用的工作環境能發現 Decision-Grill Skill。它需要由使用者明確啟動，不會自行跳出；如果你的環境尚未提供此 Skill，請依該環境或專案既有的安裝與啟用方式處理。Decision-Grill 不會自行安裝，也不依賴其他訪談工具。

開始前不必把資料備齊，但先準備以下內容會讓訪談更順暢：

- 想決定的事情與背景。
- 現有方案或候選方案。
- 期限、預算、資源及其他限制。
- 你能承受的風險，以及最在意的條件。
- 需要向外部人士確認的問題。

請只提供完成決策所需的資訊。不要貼上密碼、權杖、完整身分證明資料、金融帳密或其他不必要的敏感資料。

## 如何啟動

在 Codex CLI 中，先輸入下列明確指令：

```text
$decision-grill
```

在採用斜線指令的 Desktop 介面中，使用：

```text
/decision-grill
```

啟動後再輸入你的決策題目即可；不需要先輸入特殊參數。以下是可直接複製的例子：

```text
$decision-grill
我要決定新客服系統要選方案 A 還是方案 B；兩週內必須定案，最在意資料移轉風險與年成本。
```

```text
$decision-grill
請協助我決定產品要一次全面推出，還是先小範圍試行；目前尚不確定客服承載量。
```

```text
$decision-grill
我要決定是否採購新的分析工具。候選有三家，年度預算有限，資安審查結果仍待確認。
```

## 如何寫出好的初始題目

你可以直接用自然語言，也可以套用這個模板：

```text
我要決定：
背景：
目前方案：
已知限制：
希望完成的時間：
我最在意的條件：
仍需外部確認的事項：
```

不需要一開始就回答所有欄位。Decision-Grill 會逐步追問真正影響結果的缺口。不過，請把題目寫成「我要決定什麼」，而不是「請幫我實作什麼」；例如可問「要採用哪種通知方式」，不能要求它「幫我改好通知程式」。

## 訪談流程

1. **確認決策目標。** 它會重述你要決定的事，確認目標是否單一、明確且可在一次對話中處理。
2. **分辨事實與決定。** 它會區分 unknown fact（未知事實）與 undecided decision（尚未決定的選擇）。若一句話可能兩者皆是，會先只問一個分類問題。
3. **Coverage Scan（面向檢查）。** 它會檢查目標、利害關係人、範圍、限制、依賴、替代方案與取捨、風險、成功條件、未知與假設、範圍外事項、下一步等面向，僅針對有實質缺口的部分提問。
4. **一次處理一題。** 每一題都會說明為何重要、建議答案、替代方案與延後的影響；你可接受、改選、修改、說不知道、延後或要求說明。
5. **更新決策紀錄。** 你的回答被採納後，工具會先記錄該題的結果，再處理下一個獨立問題。
6. **處理阻礙與研究需求。** 若外部核准、依賴條件或未知事實使決策無法安全前進，會記為阻礙；若需要超出本次對話的查證，會記為待研究工作，不會假裝已查到答案。
7. **檢查收斂條件。** 它會確認重要問題、未知、依賴與面向檢查是否都已被適當處理。
8. **明確確認後才結束。** 即使摘要已完成，仍需你明確確認，才可標為 `CONVERGED` 並產出最終摘要。

因此，不是每次訪談都一定會 `CONVERGED`。資料不足、外部事實尚未取得、仍有阻礙，或你尚未確認時，訪談會保持未收斂狀態，這是正確且安全的結果。

## 狀態與紀錄怎麼看

決策紀錄中的正式狀態可這樣理解：

| 狀態 | 意思 | 簡短例子 |
| --- | --- | --- |
| `OPEN` | 目前可由你直接回答的問題。 | 「要選方案 A 或 B？」正在等你選擇。 |
| `ANSWERED` | 你已回答或接受建議，結果已記錄。 | 「選擇先小範圍試行」已記入紀錄。 |
| `BLOCKED` | 外部條件、依賴或必要未知事實使問題不能安全前進。 | 資安核准尚未取得，採購決定被阻擋。 |
| `SUPERSEDED` | 舊答案已被後來確認的新答案取代。 | 原先選 A，後來改選 B，A 的紀錄被取代。 |

還有兩個容易混淆的概念：

- `RESEARCH_REQUIRED` 是**事實或工作狀態**，不是決策狀態。例如「需向主管機關確認許可條件」是待研究工作；受它影響的採購決定仍會另列為 `BLOCKED`、`PROVISIONAL` 或 `DEFERRED`。
- `CONVERGED` 是整場訪談的收斂結果，不是單一問題的狀態。只有所有正式收斂條件都符合，而且你已明確確認後才可使用。

你也可能看到暫定或延後的記錄：它們必須是你明確選擇的結果，而不是工具為了趕快結束而自行指定。

## 三項重要產品規則

### 1. 未知事實與未定選擇不同

「我不知道是否有預算」是待確認的事實；「我還沒決定要不要增加預算」則是你的選擇。若表述不清，Decision-Grill 只會先問一個分類問題，而不是同時丟出多個新問題或替你猜答案。

### 2. 太大的目標會被轉介

若目標包含太多工作流、時間範圍過長或無法在一次對話收斂，Decision-Grill 會停止這次訪談並建議使用 `wayfinder` 拆解。它不會在這種情況下繼續面向檢查、建立新問題或自動啟動 `wayfinder`。

### 3. 不會替你實作

無論在訪談中途、摘要前或摘要後，Decision-Grill 都不會替你實作、修改檔案或執行命令。它可以幫你確認「該做什麼決定」與「下一步應找誰或查什麼」，但不會代替你執行。

## 完整使用範例

### 範例一：比較供應商

**使用者輸入：** 我們要在兩週內選客服平台。方案 A 成本較低，方案 B 的整合較完整；我最在意資料移轉風險。

**Decision-Grill 可能追問：** 這次要先決定的是否為「選擇客服平台」，而非同時完成移轉與上線？建議先把資料移轉測試結果列為選擇的接受條件。

**使用者回答：** 是，先決定平台；沒有通過移轉測試就不選。

**紀錄／結果解讀：** 目標鎖定為平台選擇。移轉測試成為接受條件；若兩家尚未完成測試，工具會保留相關問題為未解決，而不是直接宣稱已選定供應商。

### 範例二：分清未知事實與未定選擇

**使用者輸入：** 我不知道能不能把年度預算提高，所以不知道要不要選功能較完整的方案 B。

**Decision-Grill 可能追問：** 你目前不確定的是「年度預算是否可以提高」這項事實，還是「即使可以提高也是否要提高」這項選擇？

**使用者回答：** 兩者都有；先要向財務確認是否可以提高。

**紀錄／結果解讀：** 「財務是否允許提高預算」會列為未知事實或待研究工作；選擇方案 B 的決定會依影響程度列為 `BLOCKED`，或在你明確同意時暫定或延後。工具不會把「不知道」寫成已確認的決定。

### 範例三：目標過大時改用 wayfinder

**使用者輸入：** 幫我規劃公司未來三年的所有產品、組織、人力、資金和海外市場策略。

**Decision-Grill 可能回應：** 這包含多個相互依賴且跨期的目標，超出單次決策訪談的範圍；建議改用 `wayfinder` 先拆成可處理的決策地圖。

**使用者回答：** 好，我會先拆解。

**紀錄／結果解讀：** 本次不會繼續追問，也不會自動啟動其他工具。你可在拆出一個明確且有限的決策後，再開始新的 Decision-Grill 訪談。

### 範例四：要求直接實作

**使用者輸入：** 請幫我決定通知方式，然後直接修改系統並部署。

**Decision-Grill 可能回應：** 我可以協助釐清通知方式的決策、限制、風險與接受條件，但不會修改系統、執行命令或部署。

**使用者回答：** 那先比較電子郵件與簡訊，目標是降低漏看率。

**紀錄／結果解讀：** 訪談可在「選擇通知方式」這個決策範圍內繼續，例如詢問受眾、成本、送達率與風險；實作仍保持在範圍外。

### 範例五：中性商業／投資決策

**使用者輸入：** 我們要比較購買既有股份與現金增資，請幫我整理應考量的條件。

**Decision-Grill 可能追問：** 這次是否先決定「採用哪一種交易方向」，並把估值、股東權利、稅務與法規條件視為需確認的事實？

**使用者回答：** 是；估值資料還不完整，稅務與公司程序要請律師、會計師及公司負責人確認。

**紀錄／結果解讀：** 工具會整理取捨、未知事實與待研究工作，並視其重要性阻擋或延後相關決定；它不會替你下投資結論，也不會取代專業人士的意見。

## 最終摘要怎麼使用

最終摘要是決策紀錄，可作為下列工作的上游輸入：

- 會議前準備與議程整理。
- 請主管、股東或顧問確認決策與風險。
- 請律師、會計師、技術人員或政府承辦人補充外部事實。
- 製作簡報、決策備忘錄或後續執行計畫。

摘要會列出已確認與暫定的決定、假設、未知、延後問題、風險、範圍外事項與建議下一步。它不是已完成的實作，也不代表外部專業意見已確認。摘要產生後若你改變決定，可要求重新開啟受影響的項目；舊結果會以 `SUPERSEDED` 留下取代關係，並重新檢查相依項目。

## Checkpoint 與恢復訪談

每個訪談區間中，第五個真正新增並記為 `ANSWERED` 的 primary question 完成後，工具會在下一題前提供 checkpoint 或繼續訪談的選擇。選擇繼續不會重設計數，也不是收斂確認。第七個真正新增的回答完成後，工具不會再提出第八個 primary question；若尚未收斂，會輸出 `NOT_CONVERGED` checkpoint 摘要並停止。

重大財務承諾、股權或控制權、法律責任、保證、回購、賠償、重大契約義務、關鍵外部文件依賴、即將更換工作環境，或同一決策的第二次實質修改，也可能提前出現 checkpoint。相同原因若沒有實質升級，不會反覆提示。

摘要第八段固定包含 `Recommended next action`、`Next question ID` 與 `Resume point`。恢復時會從已保留的下一個未解決問題繼續，不會靠題號推算，也不會重問已確認的問題；只有明確 reopen 或新證據使舊答案失效才會重新處理。曾有實質修改的決策會在其目前所在摘要段落保留 lineage，讓恢復後仍能辨識後續修改是否已達第二次。

## 常見問題與疑難排解

### 找不到 `$decision-grill` 怎麼辦？

先確認你使用的介面與工作環境已提供該 Skill。Codex CLI 使用 `$decision-grill`；斜線指令介面使用 `/decision-grill`。若仍找不到，請依該環境或專案既有的 Skill 安裝與啟用說明處理；不要期待 Decision-Grill 自行安裝。

### 為什麼只問一個分類問題？

當一句話無法判定是未知事實還是未定選擇時，先分類才能避免把查證工作誤當成你的決定，或反過來。分類後才會處理下一個真正重要的問題。

### 為什麼沒有直接給結論？

工具可以提出建議，但不替你做真實決定。若關鍵限制、未知事實或你的取捨尚未明確，過早結論會掩蓋風險。

### 為什麼被標為 `BLOCKED`？

通常是需要的外部核准、依賴條件、事實查證或上游決定尚未完成。查看紀錄中的阻礙與受影響決定，完成或明確處理該前提後再繼續。

### 為什麼建議改用 `wayfinder`？

你的目標可能太大、多階段或包含多個決策，無法安全地在一次訪談收斂。先拆成可管理的決策地圖，再帶一個單一目標回來處理。

### 為什麼拒絕幫我執行或修改？

這是產品邊界。Decision-Grill 只做決策釐清與整理，不會實作、改檔、執行或部署。

### 為什麼尚未 `CONVERGED`？

可能仍有阻礙、重要問題、未知、未處理依賴、面向缺口，或你尚未明確確認。明確確認不能取代前述客觀條件。

### 回答錯了或決定改變時怎麼辦？

直接說明哪個決定、假設、風險或目標需要改變。工具會只重開受影響項目，將舊結果標為 `SUPERSEDED`，並重新檢查依賴關係。

### 哪些問題需要外部專業人士確認？

法律責任、契約效力、稅務與會計處理、醫療判斷、投資適合性、法規與政府程序等，通常都需要相應專業人士或機關確認。請把它們明確列為未知事實或待研究工作。

## 使用注意事項

- 採取資料最小化原則，只提供必要資訊。
- 高風險決策應取得合格專業人士的確認。
- 清楚區分事實、假設、偏好、決策與待研究工作。
- 不要為了想快點收斂而隱藏 `BLOCKED` 的證據或風險。
- 最終確認前，重新閱讀決策紀錄與摘要，確認它仍反映你的真實決定。
